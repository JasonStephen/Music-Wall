# Music Wall（Obsidian 音乐墙插件）

在 Obsidian 里用一面「唱片墙」收藏与播放网易云音乐专辑。每张唱片可用
黑胶 / CD / 磁带 / 纯封面 四种带纹理的样式呈现，点击呼出详情确认后唤起
网易云客户端播放。数据以 `.mw`（JSON）文件存于你的库中，可导入导出、走 Git 共享。

## 功能概览

- **文件即视图**：像新建 md 一样新建 `.mw` 文件，点开即渲染音乐墙（FileView：切文件/重命名/导航由框架管理）。
- **顶部栏：融入墙面的一行纯图标（固定不随滚动）**：左上角「墙名 · N 张」（点标题改名），右侧依次是
  **样式与布局 / 筛选 / 排序 / ＋ / 搜索 / ⋯** 六个图标。图标**只有图标本身**（无底色、无边框、无圆角矩形、
  无阴影，hover 只变色），并且顶栏**没有自己的底色与分隔线**——展示架的木纹背板挂在视图根上，
  顶栏与墙面是同一张画布，不再是一条孤立的白条。
- **面板从右上角展开**：🔍 搜索本墙、＋ 添加专辑都以**右上角悬浮框**出现（不再占一条底部搜索条，
  也不压暗页面；点墙面不会关掉它，方便边筛边看）；样式与布局、筛选、排序仍是**右侧滑出抽屉**。
  两者互斥，**收起途径只有三条：Esc / 面板右上 × / 再点同一图标**——点墙、点卡片、点别处
  **一律不收起**（面板没有遮罩、也不吞点击，页面照常可用）。
- **四种唱片样式 + 三种布局**：在「样式与布局」面板里以**真实唱片缩略预览**选择（黑胶 / CD / 磁带 / 封面）
  与网格 / 列表 / 展示架；预览按瓷砖尺寸完整渲染（不裁切、不空白），列表布局下样式仍可切换。
- **分组（照片墙分区）**：顶部不再有分组图标——**墙空白处右键**可「新建分组 / 展开全部分组 / 收起全部分组」；
  **分组头右键**可重命名 / 删除 / 展开收起本组；分组头**任何时候都能直接拖拽换序**（不需要编辑模式）。
  墙上按分组分区显示，每个分组头可单独展开收起（收起后组内卡片不渲染，大墙更轻）、计数常显、双击标题改名。
  删除**非空**分组必须**手动输入分组名**确认，确认后**连同组内唱片一起移出本墙**；空分组只需普通二次确认。
  新添加的专辑一律进「未分组」，之后用拖拽或卡片右键「移动到分组…」（模态选择框）归组；
  **「未分组」分区同样能单独展开收起**（右键它只有展开/收起两项——它不是一个分组）。
- **排序类型与升降序彻底分离**：「排序」面板里类型是单选（手动排序 / 添加时间 / 专辑名 / 艺术家 / 发行时间），
  升序 / 降序是**独立的两个按钮**，任意组合。
- **拖拽语义（桌面端一套原生拖拽，按编辑态分流）**：
  | 状态 | 在本墙内松手 | 拖到另一面墙 / 文件列表 |
  | --- | --- | --- |
  | 非编辑态 | **不生效**（禁止光标 + 一次性提示「先长按进入布局编辑」） | **迁移**（任何时候都能用） |
  | 编辑态（长按唱片 400ms 进入） | **排序 / 跨分组 / 拖分组头换序** | **仍然可以迁移** |
  编辑态**每次落点实时保存**，操作条上只有一个 ✓ 图标用于退出（Esc 等同），没有「取消/回滚」；
  **触屏**没有原生拖拽，长按 350ms 后走指针拖拽（编辑态内排序）。
  排序与分组都写进 `.mw`，重开标签页保持。
- **筛选（多选）**：按艺术家 / 年代 / 标签**多选**筛选（同维度 OR、维度间 AND）+ 关键词搜索，
  每项带数量、可单独或一键清除。排序键、升降序、筛选条件都随 `.mw` 落盘。
- **全局缩放**：设置页「界面缩放」50%–200%，或在墙 / 播放器内用 **Ctrl+滚轮**、**Alt+滚轮** 直接调；
  对音乐墙与播放器页（含侧边抽屉与弹窗）一起生效，缩放后视图仍精确填满窗格、内容依旧点得到。
  > 实现要点（别改回去）：缩放盒用 `transform: scale(var(--mw-zoom))` + `transform-origin: 0 0`，
  > 配 `width/height: calc(100% / var(--mw-zoom))` 反除补偿。**不能用 `zoom`**——Chromium 128+ 起
  > `zoom` 对「自身尺寸来自百分比」的元素整段失效（补偿生效、放大失效），表现正是
  > 「>100% 右侧/底部留白、<100% 内容溢出被裁」。e2e 里 `zoom` 场景会断言缩放盒 rect 等于窗格，
  > 并在四角与边中点做命中探测（只断言「根元素等于窗格」是抓不住这个缺陷的）。
  > **样式表之外还有一层 JS 像素兜底**（第七轮）：`calc()` 里的百分比一旦解析不成会**静默退化成
  > `auto`**（`width: auto` ⇒ 铺满窗格再被 `scale(0.9)` 压成 90% ⇒ 右侧一条空白；`height: auto`
  > ⇒ 内容高度 ⇒ 底部一大片空白），所以视图会在 `render()` 与 `plugin.applyZoom()` 时用
  > `zoom.ts` 的 `syncZoomBox()` 按窗格 `clientWidth/Height` 把尺寸写进行内样式，并用
  > `ResizeObserver` 跟随窗格。这正是用户报的「展示架右侧/底部留白，不开详情也有」。
  > 弹窗的尺寸上限只在**确实放大时**生效（`body.mw-zoomed`）：`z = 1` 时若也写 `max-width: 92vw`，
  > 会把每个弹窗自己的宽度（如详情面板的 680px、主题给的默认宽度）一起顶掉。
- **整块画布铺满窗格（不留白）**：`.view-content` 就是 `.mw-view` 根，主题常给它加内边距
  （Perspective 是 `padding: 12px 12px 32px`），那圈内边距会把墙/地板缩进去、四周露出一条底色 ——
  第五轮已把它强制归零，呼吸感改由内部提供（顶栏与网格各自留左右内边距）。
  > 修的时候注意：`.mw-modal-zoom .modal` 这类「后代选择器」在真机上匹配不到
  > （`modalEl` 自己就是 `.modal`），已补成 `.modal.mw-modal-zoom, .mw-modal-zoom .modal` 两种写法。
- **侧边面板不压暗页面**：样式/筛选/排序面板**没有遮罩**——不压暗背景、不遮挡顶栏图标、也不会
  吞掉点击；关闭方式：工具栏图标（开关）、面板右上 ×、Esc。
  > 曾经的遮罩扩大到整块缩放盒后盖住了顶栏图标，并且一旦实例状态与 DOM 不同步
  > （`close()` 守卫早退 / `dispose()` 不清类名）就会留下「看得见却点不动」的幽灵层；
  > 现在 `close()`/`dispose()` 都无条件清理 `is-open`，e2e 有 `no-scrim` 场景守着。
- **展示架整体同一套皮肤**：右键菜单（墙空白 / 分组头 / 卡片）用自绘木质菜单，
  弹窗带 `mw-modal--shelf` 木色皮肤，强调色由主题紫换成琥珀 `#d9a24a`——
  原生菜单与弹窗挂在 `body` 上，拿不到墙里的 token，所以分别在 `ShelfMenu.ts` 与
  `modalTheme.ts` + `modals.css` 里单独上色。网格/列表布局保持原生观感不变。
  > 面板内控件还额外与主题打了一场特异性战：`.theme-light input[type='search']:hover` 是 (0,3,1)，
  > 双类规则 (0,2,x) 必输。故 `panel-controls.css` 统一用 `.mw-view .mw-drawer …`（≥(0,3,0)）+ `!important`；
  > 搜索行主按钮必须写 `:not(.mw-panel__clearicon)`，否则 × 清空钮会被刷成实心圆（用户报的「紫色圆」）。
- **跨分组拖拽**：编辑态把唱片拖到**任意分组**的表头或空白处都能加入该组——包括**空分组**与
  **收起的分组**（这两类分区里没有卡片 DOM，落点锚点按数据算，不能再退化成「锚点 = 自己」而静默丢弃）；
  跨组悬停时目标分组整块高亮，拖到列表上下边缘会连续自动滚动（rAF，跨远距离分组也能拖到）。
- **详情面板**：左样式预览 / 右 metadata，可就地切换样式；搜索添加与播放前确认**共用同一组件**。
- **添加专辑**：工具栏「＋」→ 右上角悬浮框搜索网易云专辑 → 详情确认 → 自动抓取完整元数据。
- **三布局**：网格（大唱片）/ 多列列表（紧凑行）/ **展示架**（深色木架封套平放靠立，悬停抽出、
  vinyl 样式盘片滑出半张慢转；触屏两段式，滚动/点空白收起；文字三档在设置页「展示架文字显示」），
  每面墙独立记忆，工具栏一键切换。
- **展示架场景内详情**：点击唱片整架左滑、详情面板从右滑入（工具栏保留原位）——左侧大唱片慢转、
  右侧专辑信息 + 「▶ 播放整张」+ 编辑/迁移/复制链接/删除操作钮 + 纯展示曲目列表；「←」/Esc 返回。
  仅展示架布局生效，网格/列表仍用详情模态框。
  **背板遮罩只做视觉**（`pointer-events: none`，容器同样不拦点击）：点别处**不会**收回开盒详情，
  关闭途径 = 右上 × / Esc；点击穿透到墙，可直接点开另一张唱片换详情。
  > 覆盖层挂在**缩放盒**上而不是 `.mw-stage` 里：`.mw-stage` 带容器查询锚（= `contain: layout`）
  > 会自成堆叠上下文，`inset: 0` 只能盖住「顶栏以下」，顶栏那一条会露在黑底之上
  > （第六轮修的「背景黑色没能覆盖全屏」）。要盖满窗格的浮层都得挂在缩放盒上——抽屉/浮层同理。
- **展示架风格菜单**：架内卡片右键（触屏长按）唤出自绘深棕木纹菜单，与架子视觉一体；
  卡片不再显示悬停 ⋯/✕ 按钮，操作全部走菜单与详情页。
- **新建 / 删除**：库文件列表右键文件夹即建「新的音乐墙.mw」并打开；卡片悬停 ✕ 删除（确认框）。
- **跨墙迁移**：卡片 ⋯ 菜单或右键「迁移到其他墙…」选择目标；桌面端也可尝试拖唱片到另一面已打开的墙上（视环境）。移动语义、按专辑 ID 查重。
- **锁定语义**：锁定项禁编辑元数据（仍显示/可播放/可换样式/可删除）；经 ⋯ 菜单解锁后可改。
- **筛选 / 排序 / 搜索**：见上方「工具栏 / 分组 / 排序」三节；状态落盘于 `.mw` 的 `view` 字段。
- **响应式**：网格宽度随屏幕 `auto-fill` 自适应；窄容器下工具栏图标换行、抽屉占满宽度。
- **导入 / 导出 / Git 导入**：导入与 Git 导入在覆盖既有文件前弹确认框；Git 拉取仅桌面端。
  合并导入时，目标墙里不存在的分组会自动退回「未分组」，唱片不会凭空消失。
- **播放器页（`.mwp`）**：新建 `.mwp` 文件即得一个播放器标签页。从任意音乐墙
  **拖一张唱片进去**，或在墙上右键 / 触屏长按选「加入播放器」，即切换到该专辑并整专播放。
  页内曲目列表**只读展示**（播放顺序由客户端歌单决定，不提供点歌以免打乱顺序），
  默认**完全隐藏**，点控制条上的列表按钮从页面底部**滑出**，**Esc / 收起按钮 / 再点列表按钮**关闭。
  遮罩只做视觉（`pointer-events: none`）——点页面别处不会收起面板，其余交互照常可用。
  整页不出现滚动条（根节点锁死高度并全向裁剪），**唯一可滚动区域就是曲目列表**。
  顶栏只剩「播放器名 + 右上角一个调色盘图标（只有图标，无底色边框）」：点开从右侧滑出面板，
  内含**样式**（黑胶 = 唱片机 / CD = CD 播放器 / 封面 = 大封面，带真实缩略预览）与
  **背景**（白色 / 深色 / 封面动态取色 / 木地板）两组预设；顶栏**没有自己的底色与边框**，
  直接融进播放器背景，图标颜色跟随背景模式（白底上是深色图标，不会白底白图标）；
  **封面**背景按封面整体亮度自适应：浅色封面用深色字/图标，深色封面用浅色字 + 文字阴影
  （`accent.ts` 一次采样同时给出主色与亮度，见 `MusicPlayerView.setArtTone`）。
  **采样失败（解码/网络失败，亮度也拿不到）时不再硬铺失控的模糊封面**：移除
  `--mw-player-art` 落回 `#101216` 深色基底，白字天然可读——这正是「打开播放器一片白、
  字全看不见」的修复（浅色封面模糊后发白 + 白字 = 全隐形）；失败路径同时 `console.warn`
  留痕，缓存命中失败结果时也有同步守卫（`peekTone`），不会把失败的底图重新铺回去。
  文字颜色随背景自动适配，背景模式存入插件设置长期保留。
  > 封面背景**不叠任何压暗层**：原来的 `.mw-player.mw-bg--art::after`（先是铺满整屏的 42%→78%
  > 深色，后改成只压底部信息区）已按要求整条移除——封面背景上不再加任何 background。
  > 封面模糊底提高饱和度补色，文字可读性交给文字阴影与控制键自己的深色底
  > （见 `player.css` 的 `mw-bg--art::before` 与 `.mw-np__*` 的 text-shadow）。
  控制条为 上一首 · 播放暂停 · 下一首 · 曲目列表，**播放键随背景模式取色**：
  白色 → 靛蓝、深色 → 暖金、木地板 → 木色琥珀、封面 → 从当前封面**提取主色**
  （`requestUrl` 取字节 → Blob → canvas 采样，按封面缓存；取不到就回退**品牌蓝 `#4c5bd4`**，
  不再退主题紫；纯灰封面按封面平均色补饱和，同时给出压在强调色上的图标色，避免白底白字）。
  **没匹配到专辑 / 专辑没有封面**时不会空着：设备与「封面」背景都落到内置默认封面
  （`defaultCover.ts` 的内联 SVG：黑胶纹 + 音符；data-URI 与文档同源，离线可用、可直接采样取色）。
  墙上/详情里的封面 `<img>` 破图也会换成同一张默认封面（`disc.ts` 的 `makeImg` 兜底），
  不再只把破图 `display:none` 留一片空白。

  设备外观全部使用 `.mw-dev*` 专用类名，**不影响音乐墙上的唱片样式**。
  页面不落盘播放数据（关掉标签页即回到空态）。多个 `.mwp` 各自独立。
- **SMTC 正在播放（仅 Windows 桌面端）**：需在网易云设置中勾选「开启SMTC」。播放器页显示
  曲名/歌手/播放态、可上一首/播放暂停/下一首；音乐墙上命中的唱片加高亮环 + 角标，
  且唱片动效跟随播放态（暂停即停转）；状态栏显示迷你条，点击打开播放器。
  匹配不上时只显示信息、不高亮。网易云实测**不发布专辑名与时间轴**，故播放器页
  不提供进度条、也不显示任何时间（网易云也未实现 `TryChangePlaybackPositionAsync`：
  返回成功但无实际效果，同机 Edge 会话则可 seek），设备显示屏只显示转速 / 曲目号。
- **播放**：`orpheus://<Base64(JSON)>` 唤起客户端（协议格式经 2026 开源实现核对）。
  配置 **网易云 Cookie** 后：播放时自动创建/复用私密中转歌单「Music Wall 临时播放」（不占用已有歌单），
  把整张专辑写入该歌单并切歌单连播；也可在设置中手动指定/「从账号选择」目标歌单。
  未配置 Cookie 时降级为播放第一首，最终兜底打开网页链接。

## 开发

```bash
npm install
npm run dev          # esbuild watch（JS + CSS）
npm run typecheck    # tsc --noEmit
npm run build        # 生产构建：main.js + styles.css
```

产物 `main.js`、`styles.css`、`manifest.json` 即插件运行所需；开发时把整个目录
软链/拷贝到 `<vault>/.obsidian/plugins/music-wall/` 后在设置里启用。

### `.mw` 文件结构（schema v2）

```jsonc
{
  "version": 2,
  "name": "我的音乐墙",
  "style": "vinyl",            // 四种唱片样式
  "layout": "shelf",           // 缺省 = grid
  "items": [
    {
      "albumId": 123, "source": "search", "locked": true,
      "addedAt": "2026-01-01T00:00:00.000Z",
      "groupId": "g1",         // 缺省 = 未分组（显示在末尾分区）
      "meta": { /* 专辑元数据快照，离线可读 */ }
    }
  ],
  "groups": [{ "id": "g1", "name": "华语", "collapsed": false }],
  "order": [3, 1, 2],          // 手动排序顺序；缺省时按排序键排，首次拖动才写入
  "view": {                    // 视图状态（排序类型/升降序/多选筛选）
    "sortMode": "manual", "sortAsc": false,
    "filterArtists": ["周杰伦"], "filterDecades": ["2000s"], "filterTags": []
  }
}
```
v1 文件可直接打开（自动升级，不注入 `order`/`groups`，无意义 diff 为零）；
用旧版插件打开 v2 文件会被拒（既有的版本检查行为）。

## 已知限制与风险

- **orpheus:// 协议**需在你机器上真机验证一次；若客户端版本协议不同，只需改
  `src/core/playback.ts` 的 `buildCandidates` 候选链。最终会降级到打开专辑网页链接。
- **iOS** 只能尽力唤起 App，可能无法精确切列表；**Git 导入**仅桌面端。
- 网易云接口若触发风控/字段变更，`metadata.ts` 已把解析字段映射集中，易修；元数据快照
  存于 `.mw`，断网仍可展示。
- **SMTC 仅 Windows 桌面端**，且需网易云勾选「开启SMTC」。实测网易云只发布
  **曲名 / 歌手 / 播放状态 / 控制能力**，不发布专辑名、封面与时间轴，因此：
  - 墙上高亮靠「曲名 + 歌手」匹配专辑曲目快照，同名曲目可能歧义（匹配不上就不高亮）；
  - 播放器页不提供进度条、也不显示时间：网易云不发布时间轴，且
    `TryChangePlaybackPositionAsync` 返回成功但无实际效果（同机 Edge 会话可 seek，
    确认是网易云未实现）；设备显示屏只显示转速 / 曲目号；
  - 播放器封面取匹配到的墙上专辑封面，匹配不上时用占位。
- SMTC 由常驻 PowerShell 进程轮询（约 1s）。可在设置页「SMTC 正在播放」关闭；
  非 Windows / 移动端自动降级为空实现。
